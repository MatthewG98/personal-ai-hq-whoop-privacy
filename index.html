Privacy Policy — Personal AI HQ: WHOOP Integration

Last updated: 2026-11-10

Status: in development, not yet operational. As of the "Last updated" date above, the WHOOP developer application for this integration has not yet been successfully registered, no OAuth authorisation has taken place, no WHOOP data has been retrieved, no Google Drive storage has been set up, and no synchronisation to OpenAI / ChatGPT has occurred. No end-user data is being processed today. This policy describes the intended data handling of the integration if and when it becomes operational. It will be revised if the implementation differs from what is described here, with the date above updated.

Who this policy would cover

"Personal AI HQ — WHOOP" is intended as a private, single-user software integration to be built and operated by Matthew Greenshields for his own personal use. It is not a product offered to anyone else. The sole intended data subject and sole intended end user would be Matthew Greenshields. No other person's data would be collected or processed.

What data the integration would collect

Once operational, the integration would use the official WHOOP Developer API with OAuth 2.0 to retrieve the following data from Matthew Greenshields' own WHOOP member account, using read-only scopes only:

  • Recovery score and recovery-related heart-rate-variability values (scope: read:recovery).
  • Daily "cycle" summaries including strain and aggregated heart-rate values (scope: read:cycles).
  • Sleep duration, performance and sleep-stage summaries (scope: read:sleep).
  • Workout summaries including sport type, strain and aggregated heart-rate values (scope: read:workout).

No write access to the WHOOP account would be requested or used. No data about any other person would be collected. No location data, payment data, or contact lists would be collected.

This public policy page itself does not use cookies, analytics, advertising identifiers, or any third-party trackers, and loads no external resources. This is true today and is intended to remain true for as long as the page is hosted.

Where data would be stored

  • WHOOP OAuth credentials (the client ID and client secret issued by WHOOP, plus any refresh and access tokens later issued during an OAuth authorisation) would be held in the macOS Keychain on Matthew's personal Mac. On Apple-silicon Macs this storage is hardware-backed by the Secure Enclave.
  • Summarised health metrics — derived daily summaries in plain-text form — would be written to a private Google Drive folder tied to Matthew's personal Google account. No such folder exists today; it would be created only if and when the integration begins operating. The Google Drive folder would not be shared with any other Google account.
  • Any OpenAI / ChatGPT synchronisation is conditional and does not occur today. It would begin only if Matthew (a) completes the integration and (b) explicitly adds the Google Drive folder as a source inside his personal ChatGPT project. In that case OpenAI's ChatGPT connector service would synchronise copies of the summary files to OpenAI's systems in order to index them for retrieval during Matthew's own queries, governed by OpenAI's own published data policies for ChatGPT connectors. If the Drive source is removed, or the connector is disconnected, OpenAI would no longer sync further copies.
  • This integration would not operate any databases, public servers, or third-party cloud functions. No data would be transmitted to any party other than WHOOP (for the API calls), Google (for storage in Matthew's own Drive) and — only under the conditions described above — OpenAI.
  • Raw WHOOP API responses are not intended to be persisted to disk beyond what is needed to produce the summary files.

Retention — intended approach

The exact retention behaviour will be finalised during implementation, and this policy will be updated if it changes. The current intent is:

  • Summarised daily, weekly and monthly metrics would be kept for as long as they remain useful for Matthew's own training review, and could be deleted by him at any time.
  • Raw WHOOP API responses would not be retained.
  • Any logs produced by the integration would not contain health data, credentials, or tokens.

Who would be able to access the data

  • Matthew Greenshields, through his macOS user account and his personal Google account.
  • The ChatGPT model, when Matthew queries his own "Personal AI HQ" ChatGPT Plus project with the Google Drive source enabled — and only to the extent permitted by OpenAI's ChatGPT connector data policies.
  • WHOOP would receive only the standard OAuth 2.0 and API traffic required to serve the data requests the integration makes.
  • Google would receive only the file-upload and file-sync traffic required to keep the private Drive folder in sync with Matthew's Mac.
  • No other party would be granted access. The integration would not be shared with, licensed to, or used on behalf of any other person.

Deletion — intended approach

The concrete deletion mechanisms will depend on how the integration is ultimately implemented and on the controls WHOOP, Google and OpenAI expose. The intended approach is that, once operational, Matthew would be able to fully remove data processed by this integration by some combination of the following, as applicable:

  • Revoking the application's access to his WHOOP account using WHOOP's own privacy / connected-apps controls.
  • Removing the related items from the macOS Keychain.
  • Deleting the Google Drive folder that stores the summary files.
  • Removing the Google Drive source from his ChatGPT project and, if desired, deleting the project.
  • Deleting the local project directory on the Mac.

No formal deletion-request process is required because the data subject and operator would be the same person.

Security measures — intended

  • Only read-only WHOOP scopes would be requested at OAuth authorisation time.
  • OAuth 2.0 Authorization Code flow with PKCE (S256) is the intended authentication flow.
  • The OAuth authorisation callback is intended to use a loopback redirect (http://127.0.0.1 on Matthew's Mac). The authorisation code returned by WHOOP would be received locally by a short-lived listener on the device and then exchanged directly with WHOOP's token endpoint over HTTPS — the standard OAuth 2.0 code-for-token exchange — to obtain the access and refresh tokens. The authorisation code would not be intentionally retained after this exchange and would not be sent to any unrelated third party.
  • Credentials would be held in the macOS Keychain and would not be written to project files, shell history, or version control.
  • Tokens and health data would not be printed to logs or standard output.
  • This integration does not expose any public HTTP endpoints today and is not intended to expose any.
  • The Google Drive folder containing summaries would be private and would not be shared with any other Google account.

Changes to this policy

If the integration's data handling changes materially, this policy will be revised and the "Last updated" date above will be changed. There is no mailing list because there are no external users.
